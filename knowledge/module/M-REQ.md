# M-REQ — 요구 탐색과 수용 기준

적용: 업무 요구 stakeholder 사용자 성공 조건 질문 clarification requirements

비대상: 요구가 충분히 명시됐으면 중복 질문을 줄인다

출처 ID: video:16:14-19:43, AI-proposal. 일반화·재작성: 2026-10-30.
검증 수준: 원문 대조한 설계; 새 과제에서의 효능은 미검증.

현재 사용자가 어떤 상황에서 어떤 결정을 내리는지부터 확인한다. 현업 역할 에이전트가 제공되면 실제 사례, 입력, 현재 불편, 결과 사용법을 순서대로 묻는다. 정답이나 작업 목록을 대신 정해 달라는 요청으로 대체하지 않는다.

확인한 답변 → 기능 요구 → 실제 검증 조건을 연결한다. 모르는 내용은 가정으로 표시한다. 이미 상세한 요구에는 빠진 조건만 질문한다. 질문 개수를 점수 목표로 삼지 않는다.

최소 출력: 목표 한 문장, 필수 기능, 제약, 수용 기준. templates/INTENT.md를 필요한 만큼만 사용한다. 구현 선택과 범위 결정은 사용자가 이해하고 설명할 수 있어야 한다.
