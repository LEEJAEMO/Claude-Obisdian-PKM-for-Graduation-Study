# M-QA — 작은 구현과 검증·설명 루프

적용: 검증 test evidence 완료 결과 설명 QA workflow budget

비대상: 모든 프로젝트에 복잡한 테스트 프레임워크를 추가하지 않는다

출처 ID: note-authoring, system-operations, T-006, AI-proposal. 일반화·재작성: 2026-10-30.
검증 수준: 원문 대조한 설계; 새 과제에서의 효능은 미검증.

입력 하나에서 필수 출력까지 먼저 연결한다. 정상·경계·실패 입력 중 실제 동작을 확인하는 사례를 고른다. 예상 결과를 먼저 적고 실행 명령, 실제 출력, 통과/실패/미실행을 남긴다.

실제 실패가 발생했을 때만 실패 → 원인 → 최소 수정 → 같은 검사 재실행을 기록한다. 평가용 오류나 가짜 이력을 만들지 않는다. 최종 파일과 설명을 대조하고 원본이 보존됐는지 확인한다.

구현 중 핵심 분기마다 왜 필요한지 본인이 설명한다. 설명하지 못하는 기능은 코드를 함께 확인하고 이해하거나 범위를 줄인다. AI가 자기 산출물을 통과라 보고한 것만으로 완료하지 않는다. templates/EVIDENCE.md와 DECISIONS.md는 짧은 기록을 위한 선택 양식이다.
