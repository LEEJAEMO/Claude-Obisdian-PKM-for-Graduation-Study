# /cook — 요리 비서

냉장고 재료를 AI에게 주면 레시피를 생성하고 Obsidian에 저장한다. `[[식재료 인벤토리]]`와 `[[요리 취향 및 조건]]`을 항상 함께 참조.

## 사용 모드

| 인자 형식 | 동작 |
|----------|------|
| `/cook` | 현재 인벤토리로 레시피 1개 제안 |
| `/cook [자연어 제약]` | 제약 추가 (예: "15분 안에", "고단백", "한식") |
| `/cook --add [재료] [수량] [유통기한]` | 인벤토리에 재료 추가 |
| `/cook --remove [재료] [수량]` | 사용 후 차감 (수량 생략 시 완전 제거) |
| `/cook --list` | 현재 인벤토리 전체 출력 |
| `/cook --expiring` | 유통기한 임박(≤ 7일) 재료 목록 |

---

## 주요 경로

- **인벤토리**: `$HOME\OneDrive\문서\Obsidian Vault\2. Area\2.3 Life\Cooking\식재료 인벤토리.md`
- **요리 취향**: `$HOME\OneDrive\문서\Obsidian Vault\2. Area\2.3 Life\Cooking\요리 취향 및 조건.md`
- **레시피 저장소**: `$HOME\OneDrive\문서\Obsidian Vault\2. Area\2.3 Life\Cooking\Recipes\`
- **허브**: `$HOME\OneDrive\문서\Obsidian Vault\2. Area\2.3 Life\Cooking\! 요리 허브.md`

## 인벤토리 데이터 포맷

각 재료는 본문 섹션(`## ❄️ 냉동고`, `## 🥦 냉장고`, `## 🥫 실온 / 팬트리`)의 리스트 항목:

```
- 재료명 | 수량 | 유통기한
```

- 구분자는 ` | ` (공백-파이프-공백)
- 유통기한: `YYYY-MM-DD` 또는 `~` (모름)
- 파싱 시 `| ` 기준 split 후 strip. 필드 부족하면 나머지는 `None`.
- `## 🧂 상시 보유 조미료` 섹션은 **차감 대상 아님**, 레시피 제안 시 항상 "사용 가능"으로 가정.

---

## 실행 순서

### Step 0: 인자 파싱

입력 `$ARGUMENTS`를 파싱:

1. `--add`, `--remove`, `--list`, `--expiring` 플래그 먼저 검사
2. 플래그가 없으면 `자연어 제약`으로 간주하고 레시피 제안 모드로
3. 인자가 완전히 비면 제약 없이 레시피 제안

### Step 1: 공통 — 인벤토리 Read

항상 `식재료 인벤토리.md`를 Read. 다음을 파싱:
- `## ❄️ 냉동고`, `## 🥦 냉장고`, `## 🥫 실온 / 팬트리` 섹션의 리스트 → `{location, name, amount, expiry}` 리스트
- `## 🧂 상시 보유 조미료` 섹션의 리스트 → 조미료 목록

### Step 2A: `--list` 모드

파싱된 인벤토리를 위치별로 표로 출력:

```
❄️ 냉동고
  - 닭가슴살  150g   ~
  - 양파      1/2개  ~
  ...
🥦 냉장고
  ...
🥫 팬트리
  ...
```

유통기한이 있는 항목은 오늘(2026-04-16 등)과의 차이를 D-N 형식으로 함께 표시. 7일 이내면 ⚠️ 표시.

종료.

### Step 2B: `--expiring` 모드

파싱된 인벤토리 중 유통기한이 있고 오늘로부터 7일 이내인 항목만 출력. 디데이 오름차순 정렬. 없으면 "임박 재료 없음".

종료.

### Step 2C: `--add [재료] [수량] [유통기한]` 모드

1. 사용자가 지정한 위치를 물어본다 (기본값: 냉장고). 자연어로 "냉동고" 등이 이미 포함돼 있으면 그걸 사용.
2. `식재료 인벤토리.md`의 해당 섹션 **마지막 리스트 항목 뒤에** 한 줄 삽입:
   ```
   - {재료} | {수량} | {유통기한}
   ```
3. 유통기한이 생략됐으면 `~`로 저장.
4. frontmatter의 `updated: YYYY-MM-DD`를 오늘로 갱신.
5. `## 🔄 업데이트 이력`에 `- YYYY-MM-DD: 추가 {재료} {수량}` 한 줄 prepend.
6. 결과 보고:
   ```
   ✅ 인벤토리에 추가됨:
   - 냉장고 · 닭가슴살 · 200g · 2026-05-01 (D-15)
   ```

종료.

### Step 2D: `--remove [재료] [수량]` 모드

1. 파싱된 인벤토리에서 재료명으로 검색. 여러 건이면 사용자에게 확인 요청.
2. 수량이 지정되면 기존 수량에서 차감. 파싱 가능하면 (`150g` → `50g`). 파싱 실패(단위 불일치)하면 사용자에게 확인.
3. 수량 생략 또는 0 이하면 완전 삭제.
4. frontmatter `updated`, 이력 섹션 갱신.
5. 결과 보고:
   ```
   ✅ 차감됨:
   - 두부 · 1모 (완전 제거)
   - 닭가슴살 · 150g → 100g
   ```

종료.

### Step 2E: 레시피 제안 모드 (기본)

1. **요리 취향 Read**: `요리 취향 및 조건.md` 읽어 제약사항 파악 (단백질 30~40g, 한식/일식 선호, 웹 검증 필수, 정량 표기, 영양·보관 정보 포함 등)

2. **최근 레시피 3개 체크** (반복 방지):
   - `Recipes/` 폴더에서 `file.ctime` 내림차순 최근 3개 파일의 `주요_재료` frontmatter를 확인
   - 이 재료 구성과 **완전히 동일한** 조합은 제안하지 않음 (다른 재료 1개라도 섞을 것)

3. **유통기한 임박 재료 가중치**: 7일 이내 재료가 있으면 **우선 사용**. 프롬프트에 "⚠️ 두부(D-3), 숙주(D-2) 우선 소비" 형태로 명시.

4. **제약 반영**:
   - 사용자 자연어 제약 (`15분`, `고단백`, `한식` 등) 해석
   - `$ARGUMENTS`에 시간 언급 있으면 `조리_시간` 한도로 설정
   - 장르 언급 있으면 `요리_유형` 고정

5. **레시피 생성**:
   - 인벤토리에서 사용할 재료 + 조미료 + 가정상 보유(`요리 취향 및 조건` §🧂)
   - 외부 **실제 링크 검증 필수** (WebFetch 또는 WebSearch로 유튜브/레시피 블로그의 개별 포스팅 URL 확보. 검색 결과 페이지 URL 금지)
   - 정량(g, T, 개) 표기
   - 조리 순서 초보자 기준으로 6단계 내외
   - 영양 정보: 칼로리, 단백질, 탄수화물, 지방
   - 보관 정보: 냉장/냉동 최대 일수

6. **사용자에게 제안 표시** (저장 전 확인):
   ```
   🍳 제안: {레시피명}

   사용 재료 (인벤토리): 닭가슴살 150g, 두부 1모, 숙주 100g, 우동사리 1봉
   조리 시간: 15분 | 단백질: 33g | 유형: 일식/퓨전

   [Recipes/2026-MM-DD {레시피명}.md 에 저장할까요? (yes/수정/다른 거)]
   ```

7. **사용자 확인 후 저장**:
   - 파일명: `Recipes/YYYY-MM-DD {레시피명}.md`
   - 아래 템플릿으로 저장 (기존 `2026-04-13 닭가슴살 두부 볶음우동.md` 구조 기반)

8. **저장 후 인벤토리 자동 차감 제안**:
   ```
   💡 저장 완료. 이 레시피를 **지금 만드셨다면** 다음 재료를 차감할까요? (yes/no)
     - 닭가슴살 150g (완전 소비)
     - 두부 1모 (완전 소비)
     - 숙주 100g (완전 소비)
     - 우동사리 1봉 (완전 소비)
   ```
   사용자 yes 시 Step 2D 로직으로 차감.

```markdown

tags: [life/cooking/recipe]
date: YYYY-MM-DD
단백질_수준: 높음          # 낮음 | 중간 | 높음 (30g 이상 = 높음)
조리_시간: 15              # 분 단위, 정수
요리_유형: 일식/퓨전       # 한식 | 일식 | 양식 | 중식 | 퓨전 등

난이도: 쉬움               # 쉬움 | 보통 | 어려움
칼로리: 420                # kcal, 1회 분량 기준
사용한_인벤토리_항목:      # /cook 차감용 힌트
  - 닭가슴살: 150g
  - 두부: 1모
  - 우동사리: 1봉
```

## 에러 처리

- **인벤토리 파일이 없거나 파싱 실패**: 사용자에게 알리고 중단. 임의로 생성하지 않음.
- **재료가 거의 없음** (실질 사용 가능 항목 < 3): "인벤토리가 너무 비어 있습니다. 기본 조미료만으로 만들 수 있는 간단 요리를 제안할까요?" 확인 후 진행.
- **모든 재료가 유통기한 초과**: 경고 후 사용자에게 계속할지 확인.
- **자연어 제약 해석 실패**: 사용자에게 재확인. "15분 안에 한식, 단백질 많이" → `{시간: 15, 유형: 한식, 제약: 고단백}`.

## 관련 스킬·파일

- `[[식재료 인벤토리]]` — 단일 진실의 원천
- `[[요리 취향 및 조건]]` — AI 프롬프트 고정 제약
- `[[! 요리 허브]]` — Dataview 대시보드
- 관련 스킬: WebFetch, WebSearch (레시피 링크 검증)

## 금기 사항

- **인벤토리 파일의 frontmatter `type: cooking-inventory`를 바꾸지 말 것** (Dataview 쿼리 깨짐)
- **검색 결과 페이지 URL을 참고 자료로 쓰지 말 것** (개별 포스팅/영상만)
- **정량 없이 "적당히" 기술 금지**
- **조미료를 `/cook --remove`로 차감 금지** (상시 보유로 간주)
